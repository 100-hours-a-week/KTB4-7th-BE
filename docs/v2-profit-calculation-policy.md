# V2 순수익 비용 입력 및 계산 기준

관련 이슈: [#371](https://github.com/100-hours-a-week/KTB4-7th-BE/issues/371)

이 문서는 V2 비용 입력 API와 `ProfitCalculationService`가 공유할 금액 규칙을 정한다. 월 비용 저장·조회, 기간별 매출 조회, 순이익 계산에 적용한다.

## 1. 월별 입력값

매장과 비용 기준 월(`costMonth`, `YYYY-MM`)당 비용 행은 하나다. DB의 `cost_month`는 해당 월의 첫날로 저장한다.

| 필드 | 의미 | 입력·저장 규칙 |
| --- | --- | --- |
| `rentAmount` | 월 임대료 | 필수, 0 이상의 원 단위 정수, `BIGINT UNSIGNED` |
| `laborAmount` | 월 인건비 | 필수, 0 이상의 원 단위 정수, `BIGINT UNSIGNED` |
| `ingredientCostRate` | 월 순매출 대비 재료비 비율 | 필수, 0 이상 1 이하의 소수, 최대 소수점 넷째 자리, `DECIMAL(5,4)` |

`ingredientCostRate: 0.325`는 32.5%다. API에는 `32.5`가 아닌 `0.325`를 전달한다. `0`은 비용이 없는 유효한 입력값이며, 행이 없는 상태와 구별한다. 세 필드 중 하나라도 빠지거나, 금액이 음수·소수이거나, 원가율이 범위 또는 자릿수를 벗어나면 저장하지 않고 API 정의서의 400 응답으로 처리한다. Java `long`으로 처리할 수 없는 크기의 금액도 거절한다. 초과 자릿수를 반올림해 받아들이지 않는다. 공과금과 카드·배달 수수료는 V2 입력값과 계산에서 제외한다.

비용 입력 화면은 건너뛸 수 있다. 건너뛸 때는 비용 행을 생성하거나 0원 값으로 대체하지 않는다. 매출 업로드와 기존 매출 분석은 계속 이용할 수 있으며, 순이익 조회만 아래의 비용 누락 상태를 반환한다.

## 2. 매출 및 기간

- 조회 기간의 시작일과 종료일은 모두 포함한다. 날짜는 `sales_date`의 영업일 기준이다.
- 월별 순매출은 해당 월과 조회 기간이 겹치는 날짜의 `sales_daily_summaries.total_net_amount`를 합산한다. `menu_net_amount`를 사용하지 않는다.
- 완료·취소·비메뉴 매출을 모두 포함한다. 취소가 반영된 음수 금액도 그대로 합산하며 0으로 보정하지 않는다.
- 조회 기간에 포함된 **모든 월**에 비용 행이 있어야 계산한다. 매출이 0원인 월도 비용 행이 필요하다. 누락 월은 `COST_INPUT_REQUIRED`와 `missingCostMonths`로 알린다.
- 비용 누락 여부를 먼저 확인한다. 비용이 모두 입력됐고 매출 집계 행 자체가 없는 기간은 API 정의서의 `EMPTY`로 처리한다. 매출 집계 행이 존재하고 합계가 0원이면 계산 결과는 0원 매출을 기준으로 산출한다.

## 3. 계산식과 반올림

달력 월 `m`마다 다음 값을 구한다. `overlapDays(m)`은 조회 기간과 월 `m`의 교집합 일수이며, `daysInMonth(m)`은 윤년을 반영한 해당 월의 전체 일수다.

```text
monthlyNetSales(m) = Σ 해당 월의 total_net_amount
monthlyFixedCost(m) = rentAmount(m) + laborAmount(m)
monthlyIngredientCost(m) = roundWon(monthlyNetSales(m) × ingredientCostRate(m))
monthlyAllocatedFixedCost(m)
    = roundWon(monthlyFixedCost(m) × overlapDays(m) / daysInMonth(m))

totalNetAmount = Σ monthlyNetSales(m)
ingredientCost = Σ monthlyIngredientCost(m)
fixedCost = Σ monthlyAllocatedFixedCost(m)
netProfit = totalNetAmount − ingredientCost − fixedCost
```

`roundWon`은 소수 첫째 자리에서 원 단위 정수로 **`RoundingMode.HALF_UP`** 반올림한다. 재료비는 일별이 아닌 **월별 순매출 합계에 원가율을 곱한 뒤 월당 한 번** 반올림한다. 고정비도 월별 배분액을 월당 한 번 반올림한다. 모든 계산은 `BigDecimal`로 수행하고 `double`을 사용하지 않는다. 합계에는 중간 반올림값을 사용하며 순수익에 별도 반올림을 하지 않는다. 음수 매출에 원가율을 곱한 결과도 같은 반올림 규칙을 적용한다.

이 방식은 각 조회의 월별 재료비와 배분 고정비를 독립적으로 반올림하므로, 한 달을 여러 부분 기간으로 나눠 조회한 값의 합과 한 달 전체 조회값 사이에 원 단위 차이가 날 수 있다. V2는 개별 조회 결과의 일관성을 기준으로 한다.

일별 순이익은 월별 조회 구간의 첫날부터 날짜순으로 누적 매출·누적 포함 일수에 같은 `HALF_UP`을 적용하고, 오늘 누적 결과에서 전날 누적 결과를 뺀 재료비·고정비를 차감한다. 이 누적 차액 배분은 매출이 없는 날도 포함하며, 마지막 날까지의 일별 합계가 월별 반올림 결과와 정확히 일치한다.

## 4. 계산 예시와 검증값

| 조회 기간·입력 | 재료비 | 배분 고정비 | 순수익 |
| --- | ---: | ---: | ---: |
| 2026-03-16~2026-04-10. 3월 순매출 400만 원·원가율 0.3·고정비 310만 원, 4월 순매출 200만 원·원가율 0.25·고정비 300만 원 | 170만 원 | 260만 원 (`310만 × 16/31 + 300만 × 10/30`) | 170만 원 |
| 2026-03-01~2026-03-31. 순매출 1원·원가율 0.5·고정비 0원 | 1원 | 0원 | 0원 |
| 2026-03-01~2026-03-31. 취소 반영 순매출 -1원·원가율 0.5·고정비 0원 | -1원 | 0원 | 0원 |
| 2026-03-01~2026-03-31. 순매출 0원·원가율 0.3·고정비 100만 원 | 0원 | 100만 원 | -100만 원 |

3월·4월 예시의 고정비는 각각 160만 원과 100만 원이다. 위 검증값은 후속 계산 서비스 테스트의 기준으로 사용한다.

| 경계 조건 | 기대 결과 |
| --- | --- |
| 조회 기간에 걸친 월 중 비용 행이 하나라도 없음 | `COST_INPUT_REQUIRED`, 누락 월 반환 |
| 비용은 모두 있고 매출 집계 행이 전혀 없음 | `EMPTY` |
| 2028-02-29 하루 조회, 2월 고정비 29만 원 | 29일 중 하루이므로 고정비 1만 원 배분 |
| 매출 집계 행은 있지만 합계가 0원이고 고정비가 100만 원 | 순수익 -100만 원 |

## 5. 전기 비교와 표시

전기 순수익은 전기 날짜 범위의 일별 순매출과 **그 전기에 적용되는 월별 비용**으로 동일한 식을 다시 계산한다. 전기 비용만 누락된 경우 당기 순이익은 유지하고 전기 순이익·증감률은 `null`로 둔다. 내부 금액 차이는 두 기간 모두 계산 가능할 때 `currentNetProfit − previousNetProfit`으로 계산한다. V2 증감률은 `(현재 − 전기) / |전기|`를 소수로 표현하고 소수점 넷째 자리까지 `HALF_UP` 반올림한다. 전기 순수익이 0원이면 나눗셈이 불가능하므로 증감률은 `null`로 둔다. 전기가 적자인 경우 비율만으로 손익의 개선 여부를 설명하지 않고 두 기간의 순수익과 차액을 함께 제시한다.

전기 날짜 범위 자체는 기존 매출 분석의 `periodType`별 비교 기간 규칙을 따른다. 월별 비용 배분은 각 기간의 실제 포함 날짜 수로 계산한다.

## 6. 명세 정합성

- V2 API 정의서의 절 제목 아래 문장은 원가율을 “0 이상 100 이하의 백분율”이라고 쓰지만, 같은 문서의 요청값·예시·검증 규칙과 ERD는 `0~1` 소수다. 구현 계약은 상세 필드 규칙 및 ERD와 일치하는 **`0~1` 소수**로 정한다. 공식 문서의 해당 문장은 수정이 필요하다.
- V2 ERD의 `store_cost_items`는 `store_id`, `cost_month`, 임대료·인건비·원가율을 한 행에 둔다. 별도의 V3 비용 프로필·항목 모델을 V2 비용 입력에 적용하지 않는다.
- 금액 계산은 서버 코드에서 수행한다. 생성형 AI에는 계산을 맡기지 않는다.
- 기존 V1 `SalesAnalysisService`의 증감률은 `×100` 한 백분율 숫자이며 소수점 첫째 자리로 반올림한다. V2 순수익 분석에는 API 공통 규칙인 소수 표현을 적용하므로 V1 로직을 그대로 재사용하지 않는다.
