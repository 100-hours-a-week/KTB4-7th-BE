# V2 순이익 분석 요구사항 초안

## 1. 목적과 범위

사용자가 정보 입력 화면에서 매장의 임대료·인건비·재료 원가율을 입력하면, 선택 기간의 순매출과 해당 기간에 배분한 비용으로 예상 순이익을 확인한다. **비용 입력은 선택 사항**이며 건너뛰어도 회원가입·매출 업로드·기존 매출 분석을 계속 이용할 수 있다. 순이익 분석 화면은 비용이 있을 때 요약 금액, 이전 기간 비교, 비용 구성, 일별 추이를 제공한다.

화면에는 **순이익**으로 표기한다. 기존 API·DB의 `profit` 및 `store_cost_items` 명칭은 별개다. 이 값은 V2에서 입력·산출 가능한 비용만 반영한 **예상 순이익**이다.

이번 요구사항은 사용자가 제공한 Figma 화면 캡처·화면 설명과 기존 V2 API·ERD를 대조해 작성했다. Figma 링크의 실제 노드는 연결 계정 권한 문제로 직접 열 수 없었다. 사용자는 비용 입력을 선택 사항으로 두고, 일별 그래프·인사이트를 V2 범위에 포함하며, 원가율은 기존 API의 0~1 소수값으로 전송하기로 확인했다.

## 2. 정보 입력 화면

| ID | 요구사항 | 근거 |
| --- | --- | --- |
| IN-01 | 제목은 “순수익 분석을 위한 정보”이며, 임대료·인건비·원가율 세 입력칸, “다음단계”와 “건너뛰기” 동작을 제공한다. 현재 Figma 캡처에는 건너뛰기 동작이 보이지 않아 화면 추가가 필요하다. | 입력 화면 캡처 + 사용자 확인: 입력 선택 사항 |
| IN-02 | **저장을 선택한 경우에만** 세 값이 모두 필수다. 같은 비용 기준 월에 저장한 값이 있으면 화면 진입 시 기존 값을 표시한다. 그 월의 기록이 없다면 가장 최근 이전 월의 값을 초기값으로 보여줄 수 있어야 한다. | 화면 설명 캡처 + 사용자 확인: 입력 선택 사항 |
| IN-03 | 임대료는 월 단위 금액, 인건비는 해당 월 전체 인건비이며 사업주 본인 인건비도 포함한다. 각각 0 이상의 정수만 허용한다. | 화면 설명 캡처 |
| IN-04 | 금액 입력 중 화면에는 세 자리마다 쉼표와 우측의 고정된 `원` 단위를 표시한다. 서버에는 쉼표 없는 정수를 전달한다. 소수점·음수·문자·특수문자는 입력할 수 없다. | 화면 설명 캡처 |
| IN-05 | 원가율은 한 달 매출 중 식자재비 비율이다. 화면에는 0~100 숫자와 우측의 고정된 `%` 단위를 표시한다. 사용자가 `%`를 직접 입력하지 않는다. 소수점은 첫째 자리까지만 허용한다. | 화면 설명 캡처 |
| IN-06 | 값이 비었거나 범위를 벗어나면 각 항목 아래에 화면 설명의 오류 문구를 표시한다. 저장 실패 시 다음 화면으로 이동하지 않고 입력값을 보존한다. | 화면 설명 + 정상적인 저장 흐름 |
| IN-07 | 입력 영역 아래에 “공과금, 카드·배달 수수료 등은 포함되지 않아요. 실제 순수익과 차이가 발생할 수 있어요.”라는 안내를 항상 표시한다. | 입력 화면 설명 캡처 + V2 범위 |
| IN-08 | “다음단계”에서 세 값을 입력 당일이 속한 월의 비용으로 저장하거나 교체한 뒤 순이익 분석으로 이동한다. 월 판정은 매장 서비스 기준 시간대(`Asia/Seoul`)의 날짜를 사용한다. | 화면 + 사용자 답변 |
| IN-09 | “건너뛰기”를 선택하면 세 입력칸이 비어 있어도 비용 저장 API를 호출하지 않고 다음 화면으로 이동한다. 나중에 다시 입력할 수 있는 진입점을 제공한다. | 사용자 확인: 입력 선택 사항 |

입력칸의 문구는 제공된 화면 설명을 따른다.

| 항목 | 예시·도움말 | 누락 오류 | 범위 오류 |
| --- | --- | --- | --- |
| 임대료 | `예: 1,800,000` · “관리비를 포함한 월 임대료를 입력해주세요.” | “임대료를 입력해주세요.” | “임대료는 0 이상의 금액으로 입력해주세요.” |
| 인건비 | `예: 2,400,000` · “사장님 본인 인건비도 포함해서 입력해주세요.” | “인건비를 입력해주세요.” | “인건비는 0 이상의 금액으로 입력해주세요.” |
| 원가율 | `예: 40` · “한 달 매출 중 식자재비가 차지하는 비율을 입력해주세요.” | “원가율을 입력해주세요.” | “원가율은 0에서 100 사이로 입력해주세요.” |

원가율을 소수점 둘째 자리 이상 입력하려 하면 “원가율은 소수점 첫째 자리까지 입력할 수 있습니다.”를 표시한다.

이번 범위의 입력 화면에는 월 선택 UI가 필요 없다. 입력한 날짜의 월을 비용 기준 월로 사용한다. 달마다 서로 다른 비용을 찾아 수정하는 화면은 후속 버전으로 미룬다. 다음 달 매출 파일 업로드 시에는 **파일 업로드 날짜가 아닌 매출이 발생한 월**을 기준으로 비용 기록을 이어간다.

## 3. 저장·접근 규칙

| ID | 요구사항 |
| --- | --- |
| DATA-01 | 비용은 `store_cost_items`에 `store_id + cost_month`당 한 행으로 저장한다. 기준 월은 그 달의 1일로 정규화한다. |
| DATA-02 | 저장값은 임대료·인건비 원 단위 정수와 원가율이다. 0원 또는 0%는 입력 완료 상태이며, 비용 행이 없는 상태와 구분한다. |
| DATA-03 | 로그인 사용자의 본인 매장 비용만 조회·저장한다. 같은 매장·월의 재저장은 중복 행 생성 없이 기존 행을 갱신한다. DB의 `UNIQUE(store_id, cost_month)`로 동시 요청도 방어한다. |
| DATA-04 | 화면의 원가율 표현은 0~100%이며 소수점 첫째 자리까지 입력한다. FE가 입력값을 100으로 나누어 기존 API·ERD 형식인 0~1 소수로 전송한다. 예: 화면 `40%` → API `0.4`, 화면 `35.5%` → API `0.355`. 조회 응답은 100을 곱해 화면에 표시한다. |
| DATA-05 | 매출 파일 업로드가 완료되면 파일에 포함된 매출 월마다 비용 행이 있는지 확인한다. 해당 월에 비용 행이 없고 가장 최근 **이전 월**의 비용값이 있으면 복사해 그 매출 월의 새 행을 만든다. 기존 월 비용 행은 자동 복사로 덮어쓰지 않는다. 이전 비용 기록이 전혀 없어도 매출 업로드는 성공하며, 비용 행을 임의의 0원으로 만들지 않는다. 여러 달의 매출이 포함된 파일은 매출 월 순서대로 처리한다. |
| DATA-06 | 달마다 서로 다른 저장값을 선택·수정하는 기능은 이번 범위에서 제외한다. 이후 구현 시 선택 월의 기존 행만 갱신하고, 이미 복사된 다른 월의 값은 소급 변경하지 않는다. |

## 4. 순이익 계산

| ID | 요구사항 |
| --- | --- |
| CALC-01 | 선택 기간의 매출은 `sales_daily_summaries.total_net_amount`를 사용한다. 완료·취소·비메뉴 매출이 포함되고, 취소의 음수 금액을 그대로 반영한다. |
| CALC-02 | 해당 월 재료비는 선택 기간에 포함된 그 월의 순매출에 그 월의 원가율을 곱한다. |
| CALC-03 | 월 고정비는 임대료와 인건비의 합이다. 선택 기간이 월 일부면 `월 고정비 × 포함 날짜 수 ÷ 그 월의 전체 날짜 수`로 일할 배분한다. |
| CALC-04 | 예상 순이익은 `순매출 − 재료비 − 배분 고정비`다. 공과금, 카드·배달 수수료는 V2 계산에서 제외한다. |
| CALC-05 | 월별 재료비와 월별 배분 고정비를 각각 원 단위 `HALF_UP`으로 반올림한 후 합산한다. 계산은 `BigDecimal`을 사용한다. |
| CALC-06 | 선택 기간에 필요한 월별 비용 정보가 없으면 `COST_INPUT_REQUIRED`와 누락 월을 반환한다. 비용은 모두 있으나 매출 집계 행 자체가 없으면 `EMPTY`다. 매출 합계가 0원인 경우는 계산 가능한 기간과 구별하지 않는다. |
| CALC-07 | 비용을 건너뛰거나 아직 입력하지 않은 사용자는 순이익 숫자를 계산하지 않는다. 이 상태는 순이익 기능에만 적용되며 매출 조회·업로드의 실패 사유가 아니다. |
| CALC-08 | 현재 기간 비용은 모두 있으나 전기 비용만 부족한 경우 현재 순이익은 표시하고 전기 순이익과 증감률은 `null`로 반환한다. |

CALC-05·06은 [계산 기준](v2-profit-calculation-policy.md)과 계산 코드의 동작이다. 일별 그래프는 월별 조회 구간에서 날짜순 누적 반올림값의 차액을 배분해 기간 합계와 원 단위까지 일치시킨다.

## 5. 순이익 분석 화면

| ID | 요구사항 | 상태 |
| --- | --- | --- |
| VIEW-01 | 상단 KPI에 선택 기간의 예상 순이익과 이전 기간 대비 증감률을 표시한다. | 화면·기존 API에서 확인 |
| VIEW-02 | 매출·재료비(원가)·고정비·순이익 금액과 구성 그래프를 표시한다. | 화면에서 확인 |
| VIEW-03 | 순이익률은 `예상 순이익 ÷ 순매출 × 100`이다. 순매출이 0원이면 `-`로 표시한다. | 화면 설명에서 확인 |
| VIEW-04 | 선택 기간의 일별 예상 순이익을 날짜순 선 그래프로 표시한다. 주간 화면은 월~일 순서다. 그래프에 표시한 일별 금액의 합은 같은 기간의 KPI 순이익과 원 단위까지 일치해야 한다. | 화면 + 사용자 확인: V2 포함 |
| VIEW-05 | 인사이트 문장을 카드로 표시한다. 매출·비용·일별 순이익처럼 서버가 계산한 지표를 근거로 작성하며 금액 자체를 AI가 재계산하지 않는다. 인사이트 생성 실패가 금액 조회를 막지 않도록 결과를 분리한다. | 화면 + 사용자 확인: V2 포함 |
| VIEW-06 | 메뉴별·시간대별·요일별 순이익 그래프는 이번 범위에서 제외한다. 공통 원가율과 월 고정비를 메뉴·시간대로 나누는 기준이 정해진 뒤 후속 기능으로 다룬다. | 화면 설명, 후속 범위 |
| VIEW-07 | 비용이 누락된 기간에는 순이익 KPI·그래프·인사이트 대신 필요한 비용 월과 입력 진입점을 표시한다. 매출 등 다른 화면은 그대로 이용할 수 있다. | `COST_INPUT_REQUIRED` + 사용자 확인: 입력 선택 사항 |

화면 예시의 `매출 7,920,000원 − 원가 3,120,000원 − 고정비 2,480,000원`은 `2,320,000원`인데 표기 순이익은 `1,284,000원`이다. 따라서 캡처의 금액은 계산 기준이 아닌 시각적 예시로 취급한다.

## 6. 후속 설계 사항

1. **월별 비용 수정:** 달마다 다른 값을 찾아 수정하는 UI는 후속 기능이다. 현재 비용 저장 API의 월별 리소스 구조는 유지한다.
2. **순이익 인사이트 생성:** 현재 구현은 계산 완료 지표를 서버의 결정적 문장으로 설명한다. 외부 AI 연동 계약은 별도 확정이 필요하다.

계산 코드는 기간 합계와 일별 금액을 제공한다. 문장 생성에 실패해도 금액 응답은 제공한다.
